Final Implementation Direction

What Dev should do next

  1. Keep initial homepage product sections intentionally small — approximately 6–8 cards per block.
  2. Do not render full inactive product groups simply to hide them with CSS.
  3. Reduce repeated form/input markup inside product cards; use delegated interactions where practical.
  4. Use “View All” to move deeper browsing to existing PLP/category pages with pagination and filters.
  5. Audit GTM containers and confirm each page_view / ecommerce event fires once.
  6. Run repeatable Lighthouse tests and track field Core Web Vitals after deployment.
Acceptance Criteria

Homepage DOM remains materially below the original 7,280+ baseline.

Final Recommendation

Handoff conclusion

The original structural performance issue has been substantially improved. The recommended final direction is to keep the current optimization gains, simplify the homepage into reusable discovery-focused building blocks, reduce remaining repeated markup, and move the project into measurement and regression-control mode.
